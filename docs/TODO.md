# Дальнейшее развитие dotfiles

Задачи ниже не входят в обязательное исправление текущих ошибок. Они образуют
backlog для постепенного развития репозитория после стабилизации Zsh.

## Структура и организация

- [ ] **Объединить файлы Zsh в одном каталоге.** Убрать разделение между
  `zsh/` и `dotfiles/zsh/`, чтобы исходники и схема установки читались
  однозначно.
- [ ] **Разделить `.zshrc` на тематические модули.** Вынести историю,
  completion, плагины, интеграции инструментов и платформенные настройки в
  небольшие файлы `conf.d/*.zsh`.
- [ ] **Перейти к единому принципу размещения конфигураций.** Выбрать понятную
  схему для XDG-конфигов, файлов в `$HOME` и программ, не поддерживающих XDG.
- [ ] **Добавить локальный непубличный слой настроек.** Поддержать
  `~/.config/zsh/local.zsh` или аналогичный файл для секретов и
  машинно-зависимых значений.
- [ ] **Разделить профили машин.** Описать различия рабочего Mac, личного Mac и
  Linux-хоста данными Ansible вместо ручных изменений общих файлов.

## Надежность и тестирование

- [ ] **Добавить smoke-тест установки.** Создавать временный `$HOME`, запускать
  Dotbot и проверять обязательные ссылки и загрузку shell.
- [ ] **Добавить статические проверки shell.** Запускать `zsh -n` и ShellCheck
  для применимых shell-скриптов.
- [ ] **Настроить CI.** Проверять YAML, Ansible, Dotbot и shell-конфигурацию для
  каждого изменения репозитория.
- [ ] **Добавить проверку идемпотентности.** Дважды запускать установку и
  provisioning в тестовом окружении, где это возможно.
- [ ] **Контролировать незадекларированные зависимости.** Сопоставлять команды
  из aliases/functions с пакетами, описанными в Ansible.

## Производительность Zsh

- [ ] **Профилировать запуск shell.** Использовать `zprof` и зафиксировать
  исходное время запуска перед оптимизацией.
- [ ] **Сократить синхронную инициализацию CLI.** Кэшировать или лениво
  подключать тяжелые completion и результаты команд вроде `yc --version`.
- [ ] **Пересмотреть состав Oh My Zsh.** Удалить неиспользуемые плагины и
  оценить, нужен ли полный запуск Oh My Zsh поверх Antidote.
- [ ] **Определить бюджет запуска.** Например, поддерживать медианное время
  интерактивного запуска Zsh не более 200 мс на основной машине.

## Пользовательский опыт

- [ ] **Унифицировать fallback для современных CLI.** Использовать `bat`,
  `eza`, `fd` и другие замены только при наличии, сохраняя доступ к стандартным
  командам.
- [ ] **Пересмотреть опасные алиасы.** Оценить подмену `rm`, `cat`, `mount`,
  `jq` и `ls`, чтобы алиасы не меняли неожиданно поведение скриптов и
  интерактивных команд.
- [ ] **Организовать функции по областям.** Разделить Git, Docker, Kubernetes и
  утилитарные функции, добавить проверку аргументов и сообщения об ошибках.
- [ ] **Упростить работу с Kubernetes.** Оставить востребованные алиасы,
  удалить дубли с плагинами и добавить completion для собственных функций.
- [ ] **Выбрать и документировать prompt.** Зафиксировать Pure или Spaceship,
  его зависимости и машинно-зависимые секции.

## Provisioning и жизненный цикл

- [ ] **Сделать bootstrap одной командой.** Объединить установку ссылок,
  системных зависимостей и базовую диагностику в документированный сценарий.
- [ ] **Развести ответственность Dotbot и Ansible.** Dotbot должен управлять
  пользовательскими ссылками, Ansible — пакетами и системными настройками.
- [ ] **Обновить Linux-профиль.** Заменить устаревшие пакеты вроде `exa`,
  проверить актуальность Arch Linux dependencies и поддержку Antidote.
- [ ] **Добавить команду диагностики.** Проверять версии Zsh, наличие программ,
  битые ссылки, обязательные каталоги и конфликтующие настройки.
- [ ] **Зафиксировать политику обновления плагинов.** Описать обновление
  Antidote bundles и способ восстановления после несовместимого обновления.

## Документация

- [ ] **Расширить README.** Добавить быстрый старт, архитектуру, список
  поддерживаемых систем и описание основных каталогов.
- [ ] **Документировать восстановление новой машины.** Описать путь от чистой
  установки ОС до готового рабочего окружения.
- [ ] **Добавить troubleshooting.** Зафиксировать диагностику проблем с
  `ZDOTDIR`, Homebrew, completion, кэшем Antidote и историей Atuin.
- [ ] **Вести журнал значимых изменений.** Кратко отмечать изменения структуры,
  обязательных зависимостей и поведения shell.
